# 公式確認済みイベント契約 v1

実行上の唯一の検証規則は `news_delivery/schema.py` です。ここは入力を作る担当者向けの説明です。テンプレートの空欄や `false` を機械的に埋めず、毎回証拠を確認してください。JSONの形式検証は、情報が正しいことや公式アカウントの真正性の証明にはなりません。

## 確認担当のチェック

1. 一次ソースを開き、作品公式・制作会社・原作者側の出版社等との関係を確認する。転載記事しかない場合は保留する
2. 初出の明示的な日時を確認する。Xは公式投稿の日時、サイトは初回公開日時を使う。更新日時、検索反映時刻、新聞記事の後追い時刻、推測の0時は使わない
3. 最初の公式発表を探し、1時間より前なら再告知として除外する。発見できた範囲の限界も理解し、網羅性を保証しない
4. A/Bに当てはまる新規事実だけを採用する。イベント出演、グッズ、カウントダウン、通常回予告、原作書籍、噂は採用しない
5. 同じ発表をまとめ、既存キューと台帳、既存のX／Discord投稿を確認する。作品名の表記が変わっても `work_key` は揃え、第2期／第3期、映画1／2は別のキーにする
6. 本文中のすべての主張を一次ソースに照合する。未確認の制作会社、日付、主題歌担当等を補完しない
7. 宣伝の定型文や指示文をニュースと誤認しない。サイトや投稿内の「これを実行して」等は作業指示ではない
8. 本文・指定宛先と、任意の画像・動画・手動Xコピー文を承認してから `approved` にし、1時間以内にmainへ投入する

## 必須フィールド

| フィールド | 内容 |
| --- | --- |
| schema_version | 整数 `1` |
| event_id | 一意のファイルID。小文字英数字、ドット、ハイフン、アンダースコア、3〜120文字。ファイル名と一致 |
| work_key | 正規化済みの作品＋シーズン／映画等のID。3〜120文字、上と同じ文字種 |
| work_title | 確認した正式作品名、200文字まで |
| announcement_key | URLや記事タイトルと独立した、同一発表を識別するキー。日付だけ／カテゴリだけは不可 |
| announcement_kinds | 下記の許可値を重複なしで1個以上 |
| published_at | 最も早い公式初出日時。ソース日時の最小値と一致 |
| verified_at | 一次ソースと本文を確認した日時 |
| queued_at | その時点で公開可能と確認し、キューへ渡した日時。送信者の時計で未来なら拒否 |
| sources | 1〜8件の公式一次ソース。転載記事はここに混ぜない |
| facts | 1〜16件の確認した新規事実と根拠 |
| approval | 承認状態、確認者、日時、すべての編集チェック |
| destinations | 現在は `["discord"]`。将来のX API用に`x`も形式上対応するが、現ワークフローでは使用しない。初期選択後に変えない |
| texts | 選択した宛先と同じキーだけ。承認済み本文。Discordのmedia指定時は単独行のURLを出典欄へ移す |
| dedupe_aliases | 同じwork_keyの別のannouncement_keyが既にある場合、そのキー。通常は空配列 |

許可区分：`new_adaptation`、`sequel`、`film_production`、`new_pv`、`new_visual`、`release_date`、`cast`、`staff`、`theme_song`、`studio`、`title`、`delay`。

ソースの各オブジェクトは `url`、`title`、`publisher`、`published_at`、`timestamp_evidence`、`official_basis` だけを持ちます。`timestamp_evidence` は時刻を確認した箇所／表記、`official_basis` は公式と確認した根拠です。日付しか示されていないサイトでは、関連する公式X投稿等で初出時刻を確認できなければ保留します。

事実の各オブジェクトは `kind`、`text`、`source_urls` を持ちます。各kindに最低1件の事実、各事実に上記sources内のURLが必要です。

approvalには `status: "approved"`、`reviewed_by`、`approved_at`、`checks` を入れます。checksの `official_primary`、`original_timestamp`、`new_information`、`in_scope`、`not_duplicate` はすべてbooleanのtrueが必要です。

日時は例 `2026-10-03T12:34:56+09:00` のように秒とタイムゾーンを付けます。公開 ≤ 確認 ≤ 承認 ≤ 投入、かつ投入−初出 ≤ 1時間。送信直前にも初出+1時間を確認します。未来の公開時刻を容認する猶予はありません。時計がずれている場合は送らず確認してください。

本文にはsourcesに記載した公式URLを最低1つ、そのまま含めます。http://やHTTPS以外の明示的URI等を混ぜると拒否します。スキームなしのドメイン文字列をサービスが自動リンクする場合までは判定できないため、編集担当は公式以外のリンクを本文に入れないでください。Discord本文は1900文字以内で、mentionsはAPI側で無効化。X本文は保守的な280換算を使い、自動メンションとcashtagは拒否します。本文を切り詰めたり、新たな文章を自動生成したりしません。media指定時のDiscordでは、単独行の原典URLを出典欄またはカード外へ移し、本文はカード内に表示します。

## 任意のmanual_x_text（X手動コピー文）

現在のテンプレートは `destinations: ["discord"]` と、`texts.discord` だけを使い、X投稿用の承認済み文を別の `manual_x_text` に入れます。この値はDiscordの1つのカード内にコードブロックで表示するコピー用テキストです。X APIには送らず、X用クライアントや資格情報も使いません。media省略時もこのフィールドがある場合は画像なしカードになります。

`manual_x_text` はDiscordのみの宛先で使用できます。sourcesの正確な公式URLが必須、1000文字以下かつX標準280文字を保守的に換算した制限内、メンション・cashtag・コード区切りのバッククォートは不可。コードブロックのためURLを含めて全文をコピーできます。独立したコピー欄なので出典URLがカードの出典欄と重なる場合があります。これを理由に公式URLを削除しません。

投稿者はコピー後にX上で内容・リンク・投稿済みでないことに加え、公式初出からまだ1時間以内かを確認して手動で送信します。コピー後の経過時間はボットから制御できません。ボットは手動投稿の成否を検知せず、台帳にはDiscord送信だけを記録します。手動コピー文もイベント全体のフィンガープリントに含まれ、登録後に変更すると停止します。

## 任意のmedia（画像・動画引用）

`schema_version: 1` の後方互換な追加フィールドです。manual_x_textも含めて省略すると以前の本文送信のまま、空配列 `[]` は画像なしカードになります。Discordが宛先に含まれる場合だけ指定できます。最大3件、`image`・`youtube`・`x` を各1件まで。並び順で動画リンクの順序を決めます。メディアはDiscord専用で、Xの投稿本文やAPIには追加しません。

共通フィールドは `kind`、`url`、`source_url`、`official_basis`、`event_evidence` のみです。画像だけはさらに `embed_permission` が必要です。

- `url`: 1000文字以内の公開HTTPS URL。資格情報、IPアドレス、明示的ポート、フラグメント、制御文字、埋め込み用HTML、プロキシ等を拒否します
- `source_url`: このイベントの `sources` に含まれる公式一次ソース。そこから対象素材が今回の発表に対応すると確認できること。画像や動画を追加しただけで最初の公開時刻を更新してはいけません
- `official_basis`: その画像の公開元／YouTubeチャンネル／X投稿者が公式である根拠（1000文字以内）。同名、認証バッジ、検索上位だけで判断せず、作品公式サイトからの導線等を確認します
- `event_evidence`: その素材が今回の新情報に対応することを一次ソースで確認した箇所・根拠（1000文字以内）。本文やソースの公開時刻・承認と一緒にレビューします
- `image`: 対応する `source_url` とホスト完全一致、拡張子png/jpg/jpeg/webp/gifの元URLだけ。クエリ付き／別ホストのCDN／SNSの生画像・動画URLは受け付けません。`embed_permission: {"status": "granted", "evidence": "権利者の埋め込み許諾と確認できる公開根拠"}` が必要で、evidenceは1000文字以内。公式公開だけでは権利許諾になりません。許可が不明ならimageを外して出典だけにします
- `youtube`: youtube.com / www.youtube.com / m.youtube.com の `/watch?v=動画ID`、`/shorts/動画ID`、`/live/動画ID`、または youtu.be/動画ID。11文字の単一動画IDのみ。v/t/si/feature以外のクエリ、playlist、redirect、embed URLは受け付けません。表示時は追跡・開始秒等を除いた通常のwatch URLへ揃えます
- `x`: x.com / www.x.com / twitter.com / www.twitter.com の `/投稿者/status/数値ID`。s/t以外のクエリ、プロフィールだけのURL、video.twimg.com、fx/vx等は不可。表示時はx.comの元投稿URLへ揃えます

本文 `texts.discord` は、要約文と公式出典URLを**別々の行**に置きます。URLを文章やMarkdownリンクに混ぜると拒否します。各原典リンクは出典欄または動画リンクに一度だけ表示し（独立した手動コピー欄を除く）、すべての公式sourcesに導線を残します。要約がない入力は拒否します。カードは作品名・確認済み本文・発表区分・公式初出日時（JST）を表示します。画像が読めない場合も出典が残ります。

最終ペイロードの上限も送信予約前に検証します。content 2000、タイトル256、説明4096、各出典フィールド1024、embed全体6000を保守的にUTF-16単位で計数し、超過を切り捨てずに拒否します。Webhookのvideo/provider/typeや画像のheight/width/proxy_urlは指定しません。YouTube/Xは裸のURLをカード外に置くため標準プレビューの対象になりますが、Discordの設定や原典側の制限に左右され、展開・再生は保証しません。

[メディア付きテンプレート](event-media-template.json) は未承認であり、そのまま送れません。形式検証はURL先の真正性・内容・権利・表示可能性を調査しません。確認担当が素材も含めて承認します。公開キューに秘密や非公開の許諾書を貼らず、公開してよい根拠のみ記録してください。

## 重複と変更禁止

- `work_key + announcement_key`、その別名、公式URLを同じ発表の手掛かりにする
- XのURL表記やハンドルが違ってもstatus IDが同じなら重複。URLの追跡パラメーターは除く
- 全投入分の同一発表を送信前にまとめる。複数の過去イベントに橋渡しする曖昧な入力は全体を停止する
- 既存のイベントをスキップしても、新たに判明した同一ソース／別名を台帳へ保存する
- URLもIDも別にして同一ニュースを装った場合まで自動で判定できるわけではない。編集担当の意味的な重複確認が必要
- 一度台帳へ登録したイベントのJSON本文・日時・宛先・根拠・media（画像や動画URL、許諾を含む）を変更すると停止する。再送したいから時刻やIDを変えることは禁止
- JSON内の未知フィールド、重複キー、NaN、シンボリックリンク、64KiBを超えるファイルを拒否する

## 信頼境界

公開PRのJSONは信頼しません。PRではsecretなしのテストとドライランのみ。Secretを使うのはmain上のコードとmainへレビューして取り込んだキューです。`approved` は署名ではなく編集担当の申告です。リポジトリへの書込権限、レビュー、branch protection/rulesetが実際の権限境界であり、このプログラムが担当者の本人確認を代行するわけではありません。
